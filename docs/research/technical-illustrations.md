## Disposition

Conjunct owns reusable physical scene preparation, rendering, semantic hit
targets, state evaluation and output equivalence. A separate Rust presentation
component aligns with its existing native platform. Elixir owns host
supervision and document integration. Frameshift owns frame scenes, approved
procedures, source binding, product controls and acceptance fixtures. Its Zig
still-artwork worker remains independent.

DocShell's role is generic document-to-artifact binding, captions, locale,
fallback and presentation admission. It does not become the renderer or a
Conjunct dependency. The consumer may render a scene without a document, or
publish a document containing completed scene variants without the scene engine
installed. A second unrelated chart fixture tests that the DocShell extension
does not merely disguise a Conjunct-specific adapter.

Producer drafts were written in their owning repositories:

- Conjunct: `docs/specs/cj04/technical-illustrations.md` and
  `docs/plans/technical-illustrations.md`, serving M1-05.
- DocShell: `docs/specs/portable-artifact-capabilities.md`, with DSH-P11–P14
  in `docs/plans/documentation-sites.md`.

These contracts now have an unreleased static implementation and an exact
staged archive join. Frameshift consumes the supplied profile/schema/artifact
digests through public producer APIs. Missing capabilities remain unavailable;
no product-local generic scene compiler or documentation store fills a gap.

## Selected static implementation

The committed `data/illustrations/synthetic-photo-frame` inputs bind 16
occurrences, 33 semantic features and four exact readouts. The installed Rust
producer generates 15 states: assembled, five deterministic checkpoints, four
procedure selections, isolated connector inspection, front/top, dark and
monochrome. It emits real SVG/PNG/HTML, semantic manifests, contact sheets and
4× vector crops. Source-bound warnings and procedure order remain intact.
Both authored reports stay unknown; these figures qualify no hardware.

`packages/illustration-review` passes the completed files through the passive
producer adapter and DocShell's per-call artifact admission. The installed
archive join selects script-free SVG, validates all advertised bytes and exact
anchors, and writes a separate presentation manifest with file-relative assets.
All three producer packages have passive application specifications; no artwork
core, producer supervisor, account or network renderer is started.

The release-mode native generation observation is diagnostic timing, not a
controlled latency/RSS or maximum-profile benchmark. Browser inspection was
unavailable because the tool rejected local-file URLs. Keyboard/screen-reader,
print, high zoom, interactive worker lifecycle and additional target evidence
remain open. Generated output grants no baseline approval.

## Style and accuracy

Preserve opaque volumes, purposeful detail, stable framing and restrained tone
hierarchy. Use dimension leaders, required labels, clear warnings and multiple
subject highlights when the procedure requires them. There is no forty-part
minimum, invented fastener, arbitrary camera measurement or geometry inferred
from a reference screenshot. Decorative details are explicitly illustrative.

Readouts come from typed physical/procedure values or explicitly labelled
presentation calculations. The picture, selected feature and readout share one
bound state. Changing theme or camera cannot change compatibility, accepted
work, parts quantities or procedure readiness. Incomplete depth/cable/service
geometry stays visibly unknown.
